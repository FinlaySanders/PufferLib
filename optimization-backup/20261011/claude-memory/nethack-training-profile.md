Full-training profile of nethack @ 21 actions, hidden 128/5 layers, 1024 agents / 6 buffers / 32 threads (2026-07-06, ~180K SPS, 25M-step nsys capture, see [[nethack-env-setup]], [[cuda-backend-perf-profile]]):

- Dashboard "Forward" under Train is MISLABELED: PROF_TRAIN_FORWARD (pufferlib.cu events[3]→[4]) brackets fwd + ppo loss fwd/bwd + backward + muon + cast, i.e. the whole train iteration.
- GPU kernel time 98.8s of 140s wall; **train stream = 83.3s (84%)**, 6 rollout streams ~2.5s each. Wall split: train ~61%, env-wait ~31-38%.
- Train phase = 111 minibatches/epoch (replay_ratio 3.47 × batch 262144 / minibatch 8192). Subsystem split verified position-based (two independent captures ±1ms; encoder/mingru boundary GEMMs ±3%). PRE-cudnn: encoder 53% (dT_scatter 846µs/iter + ~1.1ms conv2-dgrad SIMT Kernel2 at 15% of memory bw + col2im/im2col 151MB col buffers), mingru 28%, muon 8%, copy 8%.
- 2026-07-06 SHIPPED cudnn conv2 (NHWC implicit GEMM, nethack-local state in ocean.cu; rows layout IS NHWC; w2p t-major buffer IS the KRSC filter — only added wgrad_krsc repack back to OIHW): conv2 fwd 490→71µs, dgrad+col2im 1317→164µs, wgrad 168→202µs. Train phase 895→715ms/epoch (-20%), encoder 478→296ms (now 41% of smaller train), clean SPS ~180K→216K (+20%). Gradient-check PASSES (tests/test_nethack_encoder.py). GOTCHAS: (1) fp32 builds must use CUDNN_FMA_MATH — TENSOR_OP silently enables TF32 and fails finite-diff checks with ~1e-2 rel err in downstream-of-dgrad grads; (2) get_cudnn_handle made thread_local (buffer threads capture graphs concurrently, like cublas); (3) cudnn algo Find at reg time keeps fwd/bwd capture-safe; (4) cudnn's anonymous "Kernel" (dgrad) must be in profile_table.py's gemm-like set. NH_HOT_T 6→7 did nothing (dT_scatter 846→851µs — traffic-bound, not contention). Remaining encoder items: dT_scatter 850µs/iter (sort+segmented-reduce is the next idea), bias_grad strided reads ~86µs×3, mingru scan (883ms bwd + 556 fwd per 777-iter capture) now the biggest single subsystem.
- GEMM-attribution: fingerprint rules (shape counts, grid geometry, duration) FAILED TWICE — muon NS, mingru-backward, and conv2-backward GEMMs collide on shape AND launch count (e.g. grid 32x5 = 5 muon 4µs + 1 conv2-dgrad 1.1ms per iter; ~30/iter small GEMMs = mingru bwd, NOT muon). Only POSITION works: nh_decode_kernel opens each train iteration, first muon_* kernel opens the optimizer section (GEMMs after = muon NS), network-section GEMMs take the nearest named kernel's class. Implemented in profile_table.py (the single source of truth — profile_nethack.sh gpu calls it); validation harness = scratchpad validate_attribution.py (landmark + neighbor ground truth).
- Env side NOT CPU-bound: only ~11.6/32 cores busy. Main thread + 6 buffer threads spin at ~100% (static_vec_omp_step / buffer_states polls + sched_yield); the ~24 OMP env workers idle at 10-50%. Env wall = per-buffer-step latency chain (rollout fwd ~92µs GPU / 198µs wall + OMP barrier on slowest env), not throughput.
- Resets are cheap: ./nethack resets → 0.29ms; ~450 resets/s costs ~0.1 core. Not a factor.
- Ranked SPS levers: (1) minibatch 8192→32768 (4× fewer iters, 4× bigger GEMMs, same math; mild optimizer-dynamics risk), (2) replay_ratio ↓ (train time ∝ minibatches; sample-efficiency tradeoff, it was swept), (3) hidden 128→256 nearly free in wall time while latency-bound → capacity for score, (4) dT_scatter optimization, (5) env phase: more OMP workers per buffer (cores idle) once train shrinks.
- py-spy --native only sees the main Python thread (OMP workers invisible); no perf (paranoid=4, no CAP_SYS_PTRACE for attach — py-spy works only spawning the target as its child). Use /proc/<pid>/task/*/stat sampling for thread utilization; note `puffer train` forks a per-GPU subprocess — sample the child with most threads.
- Repeatable tooling shipped as repo-root `profile_nethack.sh` (gpu [steps] [--reuse] | threads | env | cpu [steps]): gpu mode = ~28s nsys capture, prints a PHASE TREE (Evaluate/Train are sequential; env c_step = long pole, rollout fwd hidden by cross-buffer overlap), then kernel groups SPLIT BY STREAM = by phase (train stream adds 1:1; buffer streams hidden), memcpy, and a train/eval-bound verdict. threads = /proc CPU sampling (attaches to live trainer or self-launches); env = bench + resets; cpu = callgrind (~44x slowdown, survives NLE coroutine). Gotchas encoded: nsys exits nonzero at profiler-stop (`|| true`); sqlite denominator subqueries must use UNQUALIFIED streamId or they correlate to the outer alias and silently divide by the all-streams total. Per-phase kernel split revealed: train mingru avg 185µs (real work) vs rollout mingru 1.4µs (launch-bound); train matmul avg 15.6µs.
- Signal-based CPU samplers (gprof, gperftools SIGPROF, CPUPROFILE_REALTIME) all FAIL on NLE: the deboost.context coroutine stack-switch drops samples (empty profile) or hangs the game under SIGALRM. Callgrind (installed 2026-07-06 with gperftools) is the working gprof-equivalent. gprof additionally can't see shared libs and python is the main binary during training.
- Callgrind top env functions (random policy, dlvl 1): strncmpi 5.7%, can_reach_location 4.2%, vision_recalc 3.9%, memset 3.6%, nle_putchar/flush_screen ~4.3% (tty render still active in rl window mode), isok/lowc/mfndpos/dog_move ~10%.
