Goal set 2026-09-03: race out-of-bounds (floor strikes at 2x the drawn box) to 0, with
training kept at ~15 s wall (= default 88.65M steps at 6M SPS on the 4090).

Facts established (vec eval, 20K episodes, 3 seeds/arm; scratchpad tgt_campaign/results_pos*.tsv):
- Obs is egocentric; policy cannot see the floor. `-DDRONE_POS_OBS=1` (world pos/GRID) is
  necessary: 3.4% -> 1.9% at 1x, 0.9% at 2x, no further gain at 4x.
- Deaths = 10-20 m/s dives through downward-facing rings ~7 m above the floor; braking
  authority 1.25 g, so >13 m/s is unrecoverable. Layout-specific (4 of 16 layouts).
- Credit horizon is the lever: gamma 0.988 (sweep value) = 85 steps, dive = 80-160 steps.
  gamma 0.995 + bound_coef 1 (per-step out-of-box shaping) = 0.3% at 2x, 0.8% at 1x;
  cost = hover 6-9 cm (vs 3 cm). gamma 0.997/0.998 lower OOB but hover 15-25 cm.
- Terminal `oob_penalty` is capped by the trainer: pen 5/20/50 give byte-identical weights
  (pen 0 differs). Per-step rewards are not capped. Train-side, not patched.
- Target-encoding presets (`-DDRONE_TGT=0..6`) are all equivalent within seed noise
  (+-1 ring); only 0.05/0.5/5 is bad. Default in the header is still preset 1 (24-dim).
- SPS: 2048 agents 6.0M, 4096/32768 mb 7.8M, 8192/65536 mb 8.5M (train-bound, threads no-op).

Resume point (user: "resume drone in the morning"): run gamma 0.995 + bound_coef 1 at
8192 agents / 65536 minibatch sized to 15 s wall (~125M steps), 3 seeds; decide defaults
(DRONE_TGT back to 0? POS_OBS on?) and what goes on the web page. All env changes are
uncommitted and default-off (oob_penalty, bound_coef in config/drone.ini = 0).

**Why:** the user wants both 0 OOB and 15-s training; the two conflict at current SPS.
**How to apply:** don't re-run the ladder; start from the resume point. Related:
[[vec-backend-for-big-evals]], [[reward-config-is-user-territory]].
