The authoritative table of which NetHack weights were trained on which tree, and which cert number belongs to which (weights, tree, interface), is **`scripts/nle_stock/LEDGER.md`** in `/puffertank/pufferlib`. Update it in the same turn as any new cert or lane; a number not in the ledger does not exist.

**Why:** on 2026-09-11 three trees (box `PufferLib`, box `PufferLib_pkg`, local repo), four weight generations and three interfaces were being certed with results spread over six logs, and the user rightly called it a mess. A "15 % repo-vs-box gap" was chased for hours and turned out to compare two different kinds of number.

**How to apply — the traps:**
1. **Only `analyze.py` burn-in-adjusted mean/median over a `.ep` log is a cert** (512 agents, 14,000 eps, drop 4,000, take 10,000). A training panel `score` is a rolling final (±1000). A `CUDA_EVAL score=... games=...` line is a raw mean that includes burn-in. Never compare across kinds; always run evals with `NH_EPLOG`.
2. **`echo "$(date +%T) ... rc=$?"` always prints rc=0** — the subshell resets `$?`. Capture `rc=$?` on its own line first. Every `rc=0` in the box's `long.log` / `chalcert.log` / `claimcert.log` before 18:20 on 09-11 is meaningless; `claim2b_s504` actually segfaulted at 1.57B. Read driver stderr for `Segmentation fault`.
3. **`box_attr2.sh` hardcodes `--base.seed=7`**, so its `_s11` arms duplicate `_s7`.
4. **Claim numbers come from the box `PufferLib_pkg` tree only** (lib `bdb9896bd881`). The local repo is a dev tree (HEAD + stock-NLE landing + `cant_hold`) that nothing was trained on; do not quote cert numbers from it until a lane is promoted from it.
