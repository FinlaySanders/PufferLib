**Five fixes shipped as fork commits (user can push upstream):**
1. b9802fef9: internal[5]=u.ublesscnt export; update_inventory_method want_items/want_strs gating (obj_to_glyph kept unconditionally — display-RNG stream must stay byte-identical); panic dosave0 removal (the old sweep-killer).
2. -Bsymbolic-functions link (31bdea533): NetHack exports `alloc` etc.; puffernet's 2-arg alloc(Arena*,size_t) in the demo binary hijacked libnethack's dupstr→alloc → instant segv. Old build had IE-TLS/local binding by luck of flags.
3. sysopt once-per-process (fd111a94): sys_early_init per nle_start + sysopt_release per nh_terminate on a process-shared struct = concurrent envs double-freed the strings ("double free or corruption (fasttop)" at 4+ threads, clean serialized). pthread_once init; release no-op in lib build.
4. nle_end TLS anchor (3afb067b4): nle_end ran freedynamicdata/dlb_cleanup/nle_fflush through the CALLING thread's stale current_nle_ctx/nh_cur — vec close from main thread and truncation resets (nle_end for env A right after stepping env B) freed the WRONG env's live state → jump_fcontext segv later.
5. **THE BIG ONE** (ead9b754b): default global-dynamic TLS + fcontext coroutines + thread migration = cross-env corruption. GD TLS materializes slot addresses via __tls_get_addr; compiler caches the address in callee-saved regs ACROSS jump_fcontext suspension points; coroutine resumed on thread B writes returncontext through THREAD A's slot → env cross-linking. Vecenv uses schedule(guided) (src/vecenv.h:300) → constant migration. Repro: 64 envs schedule(dynamic) corrupts in 2 steps; diagnosing probe = integrity check that generatorcontext ∈ own stack, corrupted ptr always lands in the stack of the env currently stepped by the victim's PREVIOUS thread. Fix: CMake NLE_TLS_INITIAL_EXEC now ON (per-access %fs loads — exactly what old vendor's build did, objdump-verified 0 __tls_get_addr) + nle_yield caches ctx VALUE across the jump (value stable, slot isn't). Lesson: fibers + global-dynamic TLS = never; check objdump for __tls_get_addr when coroutines cross threads.
